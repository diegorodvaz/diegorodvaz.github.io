Cómo funciona el simulador por dentro

Diego E. Rodríguez V. · 6 min de lectura

El simulador de descenso de gradiente corre entero en el navegador: no hay servidor que calcule nada. Esta nota recorre las piezas principales, desde que escribís una función hasta que ves la trayectoria animada en 3D.

1. Las herramientas

  • HTML, CSS y JavaScript sin frameworks: el estado vive en un único objeto y cada cambio redibuja lo necesario.
  • math.js para leer la función, evaluarla y derivarla de forma simbólica.
  • Plotly.js para la superficie 3D, el mapa de curvas de nivel y el gráfico de convergencia.

Plotly pesa unos 3,5 MB. Para que el resto del portafolio cargue rápido, las librerías se descargan recién cuando el simulador está por aparecer en pantalla (con un IntersectionObserver).

2. De texto a función

Lo que escribís es texto, por ejemplo 0.5 * (x**2 + 3*y**2). El simulador:

  1. Reemplaza ** por ^, para aceptar también la sintaxis de Python.
  2. Lo convierte en un árbol de expresión con math.parse y lo compila para evaluarlo rápido.
  3. Lo prueba en cinco puntos. Así detecta símbolos desconocidos (como una z suelta) o funciones que no dan valores reales, y muestra un error legible.
  4. Calcula $\partial f/\partial x$ y $\partial f/\partial y$ con math.derivative: son las fórmulas que aparecen debajo del campo de la función.

Si math.js no puede derivar la expresión, o si se elige el modo Numérico, el gradiente se aproxima con diferencias centrales:

$$\frac{\partial f}{\partial x}(x, y) \approx \frac{f(x + h,\, y) - f(x - h,\, y)}{2h}, \qquad h = 10^{-5}\cdot\max(1, |x|).$$

El error de esta fórmula es del orden de $h^2$, mucho mejor que la diferencia hacia adelante (orden $h$). Escalar $h$ con $|x|$ evita perder precisión cuando los valores son grandes.

3. El algoritmo

Cada paso aplica $\mathbf x_{k+1} = \mathbf x_k - \alpha\,\nabla f(\mathbf x_k)$ y después revisa tres condiciones de parada:

// Un paso del descenso de gradiente (simplificado)
const p = makePoint(last.x - alpha * last.gx, last.y - alpha * last.gy);

if (!finite(p.z) || Math.abs(p.x) > 1e6) status = 'diverged';   // se fue al infinito
else if (p.norm < tol)                  status = 'converged';  // ‖∇f‖ < tolerancia
else if (k >= maxIter)                   status = 'maxiter';    // sin llegar a tiempo

Converger significa llegar a un punto crítico, donde $\nabla f = \mathbf 0$. Puede ser un mínimo, pero también un máximo o un punto de silla: los ejemplos Punto de silla y Silla de mono están para mostrar eso.

4. La curva de nivel del plano z = c

Para dibujar la intersección de la superficie con el plano $z = c$ se usa marching squares, un algoritmo clásico de gráficos:

  1. Se evalúa $f$ en una malla de puntos (de 20×20 a 120×120, según el control de resolución).
  2. En cada celda se miran sus cuatro aristas. Si en los extremos de una arista $f - c$ cambia de signo, la curva cruza esa arista.
  3. El punto exacto del cruce se estima con interpolación lineal: $t = \dfrac{c - z_a}{z_b - z_a}$.
  4. Los cruces de cada celda se unen de a pares con segmentos.

Es el mismo argumento del teorema de Bolzano, aplicado celda por celda. La curva resultante se dibuja igual en el mapa 2D y, levemente elevada, sobre la superficie 3D. Hubo una razón práctica para hacerlo a mano: un contorno de Plotly con un único nivel fallaba al redibujarse.

5. El campo vectorial

Plotly no trae un gráfico de flechas (quiver), así que las flechas se construyen como segmentos sueltos. En una grilla de 15×15 se calcula $\nabla f$, se normaliza la dirección y la longitud se hace proporcional a $\sqrt{\lVert\nabla f\rVert}$. La raíz comprime los rangos: sin ella, las flechas cerca del mínimo serían invisibles y las del borde enormes. Cada flecha se dibuja dos veces, una oscura y gruesa debajo y una blanca encima, para que se lea sobre cualquier color del mapa.

6. Que la animación sea fluida

Redibujar todo en cada paso sería lento: la superficie tiene hasta 14.400 puntos y el contorno se recalcula entero. Por eso:

  • En 3D solo se actualizan las trazas de la trayectoria (Plotly.restyle sobre tres trazas), no la superficie.
  • En 2D la trayectoria va en un <canvas> superpuesto, que usa la escala de los ejes de Plotly para ubicar cada punto. El contorno no se toca.
  • A velocidades altas se calculan varios pasos por cuadro y se dibuja una sola vez.
  • Mientras girás la cámara 3D no se redibuja nada: cada actualización reiniciaba el gesto y el giro se trababa. Los cambios pendientes se aplican al soltar el mouse, y la cámara elegida se guarda para que no vuelva a la posición inicial.

7. Integrarlo al portafolio

  • Colores: el simulador usa las mismas variables CSS que el resto de la página. Cuando cambiás entre modo claro y oscuro, un MutationObserver lo detecta y recolorea los gráficos.
  • Diseño adaptable: con container queries el simulador se acomoda según su propio ancho. En pantallas anchas los controles van en un panel lateral; en el celular, una columna con la barra de reproducción fija abajo.
  • Atajos de teclado (Espacio, →, R) que solo funcionan con el simulador enfocado, para no interferir con el scroll de la página.
