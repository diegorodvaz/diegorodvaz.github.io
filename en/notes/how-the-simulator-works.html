How the simulator works under the hood

Diego E. Rodríguez V. · 6 min read

The gradient descent simulator runs entirely in the browser: there's no server computing anything. This note walks through the main pieces, from the moment you type a function to the animated path in 3D.

1. The tools

  • HTML, CSS and JavaScript with no frameworks: the state lives in a single object and each change redraws only what's needed.
  • math.js to parse the function, evaluate it and differentiate it symbolically.
  • Plotly.js for the 3D surface, the level-curve map and the convergence chart.

Plotly weighs about 3.5 MB. So that the rest of the portfolio loads fast, the libraries are only downloaded when the simulator is about to appear on screen (using an IntersectionObserver).

2. From text to function

What you type is text, for example 0.5 * (x**2 + 3*y**2). The simulator:

  1. Replaces ** with ^, so Python syntax works too.
  2. Turns it into an expression tree with math.parse and compiles it for fast evaluation.
  3. Tests it at five points. That catches unknown symbols (like a stray z) or functions with no real values, and shows a readable error.
  4. Computes $\partial f/\partial x$ and $\partial f/\partial y$ with math.derivative: these are the formulas shown below the function field.

If math.js can't differentiate the expression, or if Numerical mode is selected, the gradient is approximated with central differences:

$$\frac{\partial f}{\partial x}(x, y) \approx \frac{f(x + h,\, y) - f(x - h,\, y)}{2h}, \qquad h = 10^{-5}\cdot\max(1, |x|).$$

The error of this formula is of order $h^2$, much better than the forward difference (order $h$). Scaling $h$ with $|x|$ avoids losing precision when values are large.

3. The algorithm

Each step applies $\mathbf x_{k+1} = \mathbf x_k - \alpha\,\nabla f(\mathbf x_k)$ and then checks three stopping conditions:

// One gradient descent step (simplified)
const p = makePoint(last.x - alpha * last.gx, last.y - alpha * last.gy);

if (!finite(p.z) || Math.abs(p.x) > 1e6) status = 'diverged';   // blew up to infinity
else if (p.norm < tol)                  status = 'converged';  // ‖∇f‖ < tolerance
else if (k >= maxIter)                   status = 'maxiter';    // ran out of iterations

Converging means reaching a critical point, where $\nabla f = \mathbf 0$. It can be a minimum, but also a maximum or a saddle point: the Saddle point and Monkey saddle examples are there to show exactly that.

4. The level curve of the plane z = c

To draw the intersection of the surface with the plane $z = c$, the simulator uses marching squares, a classic graphics algorithm:

  1. $f$ is evaluated on a grid of points (from 20×20 to 120×120, depending on the resolution control).
  2. Each cell's four edges are checked. If $f - c$ changes sign between the ends of an edge, the curve crosses that edge.
  3. The exact crossing point is estimated by linear interpolation: $t = \dfrac{c - z_a}{z_b - z_a}$.
  4. The crossings in each cell are joined in pairs with segments.

It's the same argument as Bolzano's theorem, applied cell by cell. The resulting curve is drawn the same way on the 2D map and, slightly raised, on the 3D surface. There was a practical reason to do it by hand: a Plotly contour with a single level failed when redrawn.

5. The vector field

Plotly doesn't ship an arrow plot (quiver), so the arrows are built from loose segments. On a 15×15 grid, $\nabla f$ is computed, the direction is normalized, and the length is made proportional to $\sqrt{\lVert\nabla f\rVert}$. The square root compresses the range: without it, arrows near the minimum would be invisible and the ones at the edge huge. Each arrow is drawn twice, a thick dark one underneath and a white one on top, so it reads over any color on the map.

6. Keeping the animation smooth

Redrawing everything at each step would be slow: the surface has up to 14,400 points and the contour is recomputed from scratch. So:

  • In 3D only the path traces are updated (Plotly.restyle on three traces), not the surface.
  • In 2D the path lives on an overlaid <canvas>, which uses Plotly's axis scale to place each point. The contour is left untouched.
  • At high speeds several steps are computed per frame and drawn only once.
  • Nothing is redrawn while you rotate the 3D camera: each update used to restart the gesture and the rotation would stutter. Pending changes are applied when you release the mouse, and the chosen camera is saved so it doesn't snap back to the initial position.

7. Fitting it into the portfolio

  • Colors: the simulator uses the same CSS variables as the rest of the page. When you switch between light and dark mode, a MutationObserver notices and recolors the charts.
  • Responsive layout: with container queries the simulator adapts to its own width. On wide screens the controls sit in a side panel; on phones, a single column with the playback bar pinned to the bottom.
  • Keyboard shortcuts (Space, →, R) that only work with the simulator focused, so they don't interfere with page scrolling.
